# План: тестирование UI — валидируемость человеком, вьюпорты, анимации

Статус: ВЫПОЛНЕНО (2026-07-25) — все задачи реализованы, отклонения —
в конце документа. Хвост: первые скриншот-эталоны генерятся ручным
запуском CI-workflow (галка update-visual) и коммитятся; до этого
джоб visual пропускает сравнение. План прошёл валидацию пятью свежими
моделями (pre-mortem, сверка с реальностью, скептик, YAGNI, наивный
исполнитель); все вопросы закрыты человеком.
Источник: запрос июля 2026 — тесты легко проверяются человеком; UI-тесты
ловят «компонент там, где его ждут» на разных устройствах; анимации —
только нужные, без лишних и без дёрганья.

## Вопросы

Открытые:

4. **prefers-reduced-motion.** Приложение его не уважает — опция
   Playwright сама по себе ничего не отключает. Заводим глобальный
   kill-switch `@media (prefers-reduced-motion: reduce)` в `index.css`
   (доступность + отсутствие флака) и только потом включаем
   `reducedMotion: 'reduce'` в функциональных e2e? Ждёт ответа —
   блокирует T6.

Закрытые (2026-07-25, решения человека):

1. **Мобильная поддержка обязательна** — зафиксировано в
   `docs/product.md` (раздел «Устройства»); T5 разморожен. Адаптивной
   вёрстки пока нет — скриншоты фиксируют текущее поведение на трёх
   ширинах; найденные ими переполнения — отдельные задачи вне плана.
2. **Visual-джоб** — как предложено: отдельный контейнерный CI-джоб,
   эталоны только из CI, локальный `make verify` visual не гоняет.
3. **`transition-all` кнопки чиним** точечно в vendored
   (`transition-colors`), а не заносим в исключения — вечное
   исключение хуже двухсловного диффа.
5. **Карта «приёмка → тесты»** — критерии атомизируем, rust-тест —
   валидная ссылка.

## Что уже есть (сверено валидацией; не делать повторно)

- Playwright 1.61.1, один проект `chromium` (Desktop Chrome),
  `toMatchAriaSnapshot`/`toHaveScreenshot` встроены; trace
  retain-on-failure; стенд поднимает сам Playwright.
- **Заголовки тестов фронта уже по-русски** — и vitest, и e2e читаются
  как сценарии. Осталась только карта «приёмка → тесты».
- Анимации по факту: vendored shadcn (`button` — `transition-all`,
  `input` — `transition-colors`) и тосты sonner (transform/opacity/
  height + бесконечный `sonner-spin`); `tw-animate-css` в сборке даёт
  0 keyframes; `@media (prefers-reduced-motion)` в приложении нет.
- Адаптива нет: во всём `web/src` вне vendored — ноль responsive-
  классов; ARIA-дерево на любом вьюпорте идентично.
- CI: e2e-джоб нативный (ubuntu-latest, только chromium), контейнера
  «как CI» не существует; HTML-репортёр не настроен, артефакты отчёта
  не выгружаются; `globalTimeout: 300_000` включает сборку стенда;
  `failOnFlakyTests` в CI.
- Поведение снапшотов: ARIA — subset-семантика (лишний элемент тест не
  ломает), тексты входят в снапшот, дефолтный путь БЕЗ имени проекта
  (вьюпорты перезаписали бы один файл); скриншоты — путь без платформы
  (локальный `--update-snapshots` молча затёр бы CI-эталоны);
  `toHaveScreenshot` сам глушит анимации на время снимка.

## Решения (по итогам валидации)

- **Схема UI — ARIA-снапшот, но один на страницу (desktop), не
  per-viewport.** Адаптива нет — три копии охраняли бы пустое
  множество. ARIA видит структуру и порядок DOM, но не геометрию и не
  CSS-перестановки (`order`, grid) — геометрию ловят только скриншоты.
  Свой DSL не изобретаем.
- **«Компонент там, где ждут» на устройствах — только скриншоты.**
  Три ширины как явные `viewport` в проектах chromium (дескрипторы
  `iPhone 15`/iPad не используем: тянут WebKit, которого нет в CI;
  `devices['iPad']` вообще не существует). Safari осознанно не
  проверяем. Имена файлов эталонов — явные латинские
  (`toHaveScreenshot('login-mobile.png')`): кириллица из заголовков в
  именах файлов — NFD/NFC-конфликт macOS/linux.
- **Инвариант анимаций — статический чек, не рантайм.**
  `document.getAnimations()` — снимок момента: 150-мс транзишен уже
  закончился, проверка зелёная вакуумно. Вместо этого скрипт по
  собранному CSS (`web/dist/assets/*.css`): в `transition`/`animation`
  запрещены layout-свойства (width/height/top/left/margin/padding) и
  `all`. Детерминированно, без браузера. Рантайм-проверка остаётся
  одна: бесконечные анимации ⊆ allowlist (сейчас — только
  `sonner-spin`), их `getAnimations()` ловит надёжно.
- **Плавность (FPS) не меряем** — на CI это флак; причина дёрганья
  убита статическим чеком, глаза смотрят film strip трейса.
- **`video: 'on'` не включаем** — кастомных анимаций нет, film strip
  уже есть; видео вернуть motion-спеком при первой кастомной анимации.
- **Функциональные e2e остаются на desktop** — ветвления и ошибки
  живут уровнем ниже (shift-left из writing-tests).

## Задачи

### T1. Карта «Приёмка → тесты» в use case (S)

- В UC-001/UC-002 — раздел «Приёмка → тесты»: критерии атомизировать,
  против каждого — имя теста (rust-функция или заголовок спека) либо
  честное «нет теста». Найденные дыры — в журнал как долг, не чинить
  в этой задаче.
- Конвенцию (раздел обязателен, обновляется в той же правке, что тест)
  дописать в скилл `writing-tests`.
- Приёмка: человек по use case видит, что проверено, не читая код.

### T2. HTML-отчёт Playwright артефактом CI (S)

- `reporter`: локально `list`, в CI `html` (open: never); в e2e-джоб —
  `actions/upload-artifact` (пин по SHA), retention ~14 дней, имя
  `playwright-report`.
- Приёмка: по красному e2e человек скачивает артефакт и видит трейс
  с film strip, не запуская ничего локально.

### T3. Статический чек анимационных свойств (S)

- `scripts/check-animations.sh` (или node-скрипт): собрать фронт уже
  собирает CI/e2e — по `web/dist/assets/*.css` проверить, что
  анимируются только не-layout свойства; `transition-property: all` —
  запрещён. Исключения — файлом-allowlist с причиной строкой.
- Сюда же — правка vendored `button.tsx`: `transition-all` →
  `transition-colors` (закрытый вопрос 3).
- Подключить в CI после сборки фронта (в `make check` нельзя — нужен
  dist). В `docs/toolbox.md` — строка про скрипт.
- Приёмка: `transition: width` в любом компоненте — красный CI;
  проверено фикстурой при написании.

### T4. ARIA-схемы ключевых страниц, desktop (M)

- `web/e2e/layout.spec.ts`: вход (LoginPage), список (ItemsPage),
  настройки (SettingsPage) — `toMatchAriaSnapshot` с явным
  `pathTemplate` (файлы `.aria.yml` рядом со спеком, без платформы в
  пути). Снапшот — верхняя структура страницы (роли, порядок), не
  каждый текст: правка словаря не должна перекатывать все схемы.
- Приёмка: пропажа поля или перенос блока в DOM ломает тест, дифф
  читается как YAML; правка одной строки локали не трогает снапшоты
  (проверить при написании).

### T5. Скриншот-эталоны трёх ширин (M — вопросы 1–2 закрыты, можно)

- Отдельный playwright-проект(ы) `visual-*`: chromium с явными
  viewport (desktop 1280, tablet 768, mobile 393), те же три страницы,
  явные имена png, маски на `DateTime`, `timezoneId: 'UTC'` в config
  (иначе локальные и CI-строки времени расходятся), допуск
  `maxDiffPixelRatio: 0.01`.
- Гоняется ТОЛЬКО в отдельном CI-джобе в контейнере playwright
  (`--forbid-only`, свой timeout); в локальный `make e2e` не входит
  через `--project`-фильтр (не `test.skip` — его ловит
  check-suppressions). Обновление эталонов — ручной запуск того же
  джоба в update-режиме, эталоны забираются артефактом и коммитятся.
- Первая генерация эталонов — до включения сверки (иначе
  `failOnFlakyTests` покрасит джоб на «missing golden → retry passed»).
- `globalTimeout` основного конфига не трогаем — у visual свой бюджет
  в своём джобе.
- Приёмка: наезд/переполнение на любой из трёх ширин — красный
  visual-джоб с картинкой-диффом в артефакте.

### T6. Kill-switch reduced-motion (S — после вопроса 4)

- `index.css`: `@media (prefers-reduced-motion: reduce)` глушит
  transition/animation глобально; после этого в функциональные
  проекты Playwright — `reducedMotion: 'reduce'`.
- Тест: с эмуляцией reduce на странице нет идущих анимаций
  (вот здесь `getAnimations()` уместен — проверяем пустоту).
- Приёмка: тест зелёный; сонер-тост при reduce появляется без
  анимации.

### Документация (входит в задачи, не отдельно)

- `architecture.md`: раздел про тестовую инфраструктуру фронта
  (вьюпорты, эталоны, где что гоняется) — в той задаче, которая
  первой введёт новый механизм (T3/T5).
- Каждая задача — запись в `docs/journal.md` (правило проекта).

## Осознанно не делаем (и почему)

- Per-viewport ARIA-снапшоты — адаптива нет, копии охраняют пустое
  множество; вернуть при первом responsive-брейкпоинте.
- Рантайм-манифест всех анимаций через `getAnimations()` — гонка со
  150-мс транзишенами, вакуумно-зелёный; заменён статическим чеком T3.
- FPS/джанк-метрики в CI — флак; причина джанка закрыта T3.
- WebKit/Safari — не ставим ради эмуляции: ограничение записано.
- Функциональные e2e на всех вьюпортах — ×3 времени без новых багов.
- Свой DSL схемы UI, Storybook/Chromatic, boundingBox-математика.
- `video: 'on'` — film strip трейса достаточно; видео — при первой
  кастомной анимации вместе с motion-спеком.
- Скрипт-сверка карты «приёмка → тесты» — пока конвенция; триггер на
  скрипт: два расхождения карты с тестами, найденные на ревью.

## Порядок

T1, T2, T3 — независимы, можно сразу (все S). T4 — после T1.
T5 — разморожен (вопросы 1–2 закрыты), самая дорогая часть — последним
из основных. T6 — после ответа на вопрос 4. Триггеры воскрешения
вырезанного — в антисписке.

## Что сделано иначе, чем в плане (и почему)

- **T4**: схемы живут inline в `layout.spec.ts`, а не отдельными
  `.aria.yml` с pathTemplate. Схема пишется руками как ожидание (это и
  был исходный запрос «описывать UI схематически»), а не генерится
  прогоном — значит, нет ни проблемы путей/платформ, ни рефлекса
  «обновить не глядя». Подписи элементов в схеме — русские (как во всех
  e2e по конвенции репозитория); лишние тексты страниц в схему не входят.
- **T5**: visual-слой работает на собранном фронте со стабами API
  (`vite preview` + `page.route`), а не на полном стеке — Rust и
  Postgres в джобе не нужны, данные детерминированы, маски не
  понадобились вовсе. Вместо `make update-screens` через локальный
  Docker — ручной запуск CI-workflow с галкой `update-visual` и коммит
  артефакта: локальная генерация на Apple Silicon дала бы arm64-рендер,
  не совпадающий с amd64 в CI. Локальный `make visual` прогоняет
  страницы без сравнения эталонов (`ignoreSnapshots` вне CI).

## Итоги валидации (что изменилось после пяти ракурсов)

Принято: адаптива и кастомных анимаций нет — per-viewport ARIA и
рантайм-манифест выброшены (YAGNI, сверка); «образ как CI» не
существует — visual вынесен в отдельный контейнерный джоб с генерацией
эталонов только в CI (pre-mortem, скептик); `reducedMotion` без
kill-switch в CSS — фикция (все); `getAnimations()` как инвариант —
гонка (скептик); кириллица в именах эталонов, платформа в путях,
subset-семантика ARIA, globalTimeout, failOnFlakyTests×missing-golden,
отсутствие HTML-репортёра — учтены задачами (исполнитель, сверка).

Отклонено: «выбросить скриншоты целиком» (YAGNI) — переполнение на
мобильной ширине уже реально (`max-w-xl` > 393px), а требование «компонент
там, где ждут» — явное; компромисс: T5 заморожен до продуктового ответа
на вопрос 1. «Правило про анимации текстом вместо теста» (YAGNI) —
статический чек дешевле правила: 30 строк скрипта против дрейфа ревью.
