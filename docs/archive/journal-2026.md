## 2026-07-24 — Записи стали личными

**Что сделано.** У записи появился владелец. Список показывает только свои
записи, чужую нельзя ни увидеть, ни удалить — ответ такой же, как для

следующий домен скопирует именно этот способ.

**Как проверить.** `make test` — тест «пользователь Б не видит и не удаляет
запись пользователя А».

## 2026-07-24 — Приложение защищено снаружи

**Что сделано.** Запрос не может длиться дольше 15 секунд, тело больше
мегабайта не принимается (на входе и регистрации — 16 КБ). Запросы,
меняющие вход в систему, отклоняются, если пришли с чужого сайта.
Заголовок с адресом клиента от прокси учитывается только при
`TRUST_PROXY=true` — иначе лимит запросов обходился подделкой заголовка.
Caddy добавляет заголовки безопасности и правильно кэширует статику.

**Зачем.** Дыры, найденные ревизией: без прокси лимит обходился, а долгий
или огромный запрос занимал ресурсы столько, сколько захочет клиент.

**Как проверить.** `make test` — тесты на чужой Origin и слишком большое
тело; заголовки видно в smoke-проверке образа в CI.

## 2026-07-24 — Готовность, версия и аккуратная остановка

**Что сделано.** Появились `/api/health/live` (процесс отвечает),

стартовал, не дожидаясь приложения.

**Как проверить.** `curl /api/health/ready` и `/api/version`; в CI появился
джоб, который собирает образ и проверяет это на нём.

## 2026-07-24 — Вся конфигурация читается в одном месте

**Что сделано.** Полтора десятка разрозненных чтений переменных окружения
собраны в `core/config.rs`: настройки читаются и проверяются один раз до
старта. `JWT_SECRET` теперь обязателен на старте — раньше приложение
поднималось без него и падало на первом входе. Секреты обёрнуты в тип,
который не печатает своё содержимое в логах. Возврат `env::var` в домены
запрещён автоматической проверкой.

**Зачем.** Неверная настройка должна означать «процесс не поднялся», а не
«упало через неделю у первого пользователя».

**Как проверить.** Запустить api без `JWT_SECRET` — понятная ошибка сразу;
`cargo test -p server --lib` — тест валидации и того, что секрет не
печатается.

## 2026-07-24 — Проверки цепочки поставки в CI

**Что сделано.** Новый джоб `policy`: cargo-deny (уязвимости, лицензии,
источники зависимостей), поиск секретов в коде (gitleaks), проверка
зависимостей фронта (OSV-Scanner), проверка самих сценариев CI
(actionlint) и конфигурации робота обновлений. Неиспользуемые зависимости
ловит cargo-machete — уже нашёл одну и убрал. Все сторонние действия в CI
закреплены по неизменяемому идентификатору коммита, а не по метке.
CodeQL не подключаем: репозиторий приватный, без платной подписки он
недоступен; замену городить не стали.

**Зачем.** Уязвимая или подменённая зависимость — самый простой способ
получить чужой код в проде.

**Как проверить.** Джоб `policy` в CI; локально — `cargo deny check`
(нужна сеть) и `cargo machete` (входит в `make check`).

## 2026-07-24 — Линтер фронта, таблица запретов clippy, запрет заглушек

**Что сделано.** У фронта появился линтер и форматтер — Biome (ESLint не
подходит: он несовместим с нашей версией TypeScript). Он же запрещает
хардкодить тексты прямо в разметке мимо словарей. У Rust заведена короткая
таблица запретов: unsafe, `unwrap`/`expect`/`panic` вне тестов, отладочный
вывод, `TODO`. Отдельный скрипт ловит попытки заглушить проверку:
`@ts-ignore`, запуск одного теста вместо всех, отключение линтера на весь
файл, чтение окружения мимо конфигурации. Хук после каждой правки файла
проверяет только этот файл и остаётся быстрым.

**Зачем.** Проверки, которые легко обойти молча, не защищают ни от чего.

**Как проверить.** `make check`; попробовать добавить `unwrap()` в код
домена или `@ts-ignore` на фронте — проверка упадёт.

## 2026-07-21 — Готовность к проду: письма, защита от перебора, деплой

**Что сделано.**
1. Подтверждение почты: после регистрации приходит письмо со ссылкой,
   ссылка одноразовая и живёт сутки (UC-001.8). Вошедшим через VK/Яндекс
   письмо не нужно — их адрес уже подтверждён.
2. Настоящая отправка писем: задан адрес SMTP-сервера (`SMTP_URL`) —
   письма уходят наружу; не задан — как раньше копятся в таблице outbox
   (так работают разработка и тесты).
3. Фоновый работник внутри того же процесса: рассылает письма из очереди
   и раз в час подчищает протухшие одноразовые токены. Без Redis и
   отдельных сервисов — очередью служит Postgres.
4. Защита от перебора паролей: ручки входа и регистрации пускают не
   больше 30 запросов в минуту с одного адреса (настраивается).
5. Деплой одним файлом: `compose.prod.yaml` поднимает HTTPS (Caddy сам
   получает сертификат), приложение, базу и ежесуточный бэкап с хранением
   последних 7 копий.
6. Интерфейс: страница «не найдено», экран «что-то пошло не так» вместо
   белого экрана при ошибке (ошибка улетает в логи сервера), всплывающие
   уведомления, кнопка тёмной темы.
7. Список записей отдаётся страницами (новые сверху, кнопка «Показать
   ещё») — образец пагинации для будущих списков.
8. Внешним браузерным клиентам можно открыть API переменной
   `CORS_ORIGINS`; по умолчанию закрыто.
9. Обновления зависимостей теперь приносит робот Renovate еженедельным PR.

**Зачем.** Это долги перед публичным запуском (UC-001) и вещи, которые
каждый проект собирает заново: теперь шаблон умеет их из коробки.

**Как проверить.** `make verify`; письма — зарегистрироваться и открыть
ссылку из таблицы outbox_emails (или настроить SMTP_URL); деплой — раздел
«Деплой» в `docs/architecture.md`.

нарушителях). Два разросшихся файла разрезаны по смыслу: HTTP-слой входа —

тесты входа — на три сценарных файла. Общий тестовый пароль вынесен в одно
место. В архитектуре зафиксировано решение: сервер НЕ генерируется из
описания API — наоборот, описание генерируется из кода (генератор кода
понадобится только для клиента к чужому API).

**Зачем.** Большие файлы съедают контекст — и человеку, и нейронке;
теперь разрастание ловится автоматически, а не по ощущениям.

**Как проверить.** `make check` — в нём новый шаг проверки размера;
`sh scripts/check-file-size.sh` можно запустить отдельно.
