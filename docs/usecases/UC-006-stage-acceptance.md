# UC-006 — Приёмка этапа перед оплатой

Статус: запланировано, не реализовано.

## Зачем (бизнес-ценность)

Бригада говорит «черновая готова, оплатите этап». Скрытые работы
(штробы, трассы, стяжка) можно проверить только сейчас — потом они
закроются отделкой. Чек-лист с фото-дневником — единственный шанс
проверить и единственная доказательная база при споре.

## Актёры

- Пользователь, у которого бригада сдаёт этап.
- Система — чек-листы этапов и хранение фото-дневника.

## Сценарии

### UC-006.1 Проверка по чек-листу
1. Пользователь открывает чек-лист своего этапа (пример для электрики
   до штукатурки: трассы сфотографированы? глубина штробы? сечения
   кабеля по нагрузкам? группы в щите подписаны?).
2. Допуски объяснены простым языком («стяжка: просвет под 2-метровым
   правилом ≤ 2 мм») — без отсылок к СНиПам в лоб.
3. По каждому пункту — фото; провальные пункты помечаются
   «не оплачивать, пока не устранено».

### UC-006.2 Фото-дневник
Фотографии сохраняются по пунктам и датам. Дневник накапливается за
весь ремонт и доступен пользователю всегда — это его архив.

### UC-006.3 Оплата
Входит в пакеты с приёмкой этапов (цены — `docs/product.md`).

## Не входит (осознанно)

- Выезд специалиста на объект — только самостоятельная проверка
  по чек-листу.
- Автоматическая оценка фото нейросетью — сначала ценность в самом
  чек-листе; распознавание дефектов по фото — отдельное решение потом.
- Юридическое заключение для суда — дневник это доказательства
  «для разговора», не экспертиза.

## Критерии приёмки

- Чек-листы существуют для каждого этапа типового ремонта, и каждый
  пункт сформулирован без строительного жаргона.
- Фото привязываются к пункту и дате; дневник открывается с телефона
  (фотографируют именно им).
- Пункт «не оплачивать, пока не устранено» виден в сводке этапа.
