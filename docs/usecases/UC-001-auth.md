# UC-001 — Учётные записи и вход

Статус: реализовано. История разработки — в `docs/journal.md`.

## Зачем (бизнес-ценность)

Почти любому бизнес-продукту нужны учётные записи: без них нет личных
данных, оплат и ролей. Делаем один раз в шаблоне — каждый следующий проект
получает готовый, безопасный вход.

## Актёры

- Гость — человек без учётной записи.
- Пользователь (роль `user`).
- Администратор (роль `admin`).

## Сценарии

### UC-001.1 Регистрация
1. Гость вводит email и пароль (мин. 8 символов).
2. Система создаёт учётную запись с ролью `user` и сразу выполняет вход.
- Ошибки: email занят; пароль короче минимума. Сообщения — на языке гостя.

### UC-001.2 Вход по паролю
1. Гость вводит email и пароль.
2. Если у учётной записи включена 2FA — система просит одноразовый код
   (см. UC-001.5), иначе вход выполнен.
- Ошибки: неверная пара email/пароль (без уточнения, что именно неверно).

### UC-001.3 Обновление сессии
Фронт незаметно продлевает вход (refresh-токен в защищённой cookie,
ротация при каждом использовании; украденный старый токен бесполезен).

### UC-001.4 Восстановление пароля
1. Гость указывает email.
2. Система отвечает одинаково, существует email или нет (не раскрываем
   базу), и отправляет письмо со ссылкой (токен живёт 1 час, одноразовый).
3. Гость задаёт новый пароль; все активные сессии отзываются.

### UC-001.5 Второй фактор (TOTP)
1. Пользователь в настройках включает 2FA: система показывает QR-код,
   пользователь подтверждает шестизначным кодом из приложения.
2. При входе после пароля запрашивается код из приложения.
3. Отключение 2FA — по действующему коду.

### UC-001.6 Вход через VK / Яндекс
1. Гость жмёт «Войти через …» и подтверждает доступ у провайдера.
2. Система находит или создаёт учётную запись по внешнему идентификатору.
- Подключение провайдера — конфигурацией, без изменения кода (`docs/oauth.md`).

### UC-001.7 Роли
`admin` может то же, что `user`, плюс административные операции.
Проверка роли — на бэкенде на каждом защищённом маршруте.

### UC-001.8 Подтверждение почты
1. После регистрации система отправляет письмо со ссылкой (токен живёт
   24 часа, одноразовый); пользователь при этом уже вошёл и работает.
2. Переход по ссылке и нажатие «Подтвердить адрес» ставит отметку
   «почта подтверждена» (видна в API как `email_verified`).
- Вошедшим через VK/Яндекс письмо не шлём: адрес уже подтверждён провайдером.
- Что закрывать для неподтверждённых — решает конкретный продукт; шаблон
  только хранит и отдаёт признак.

### UC-001.9 Защита от перебора
Все ручки входа/регистрации/восстановления ограничены по частоте с одного
IP-адреса (по умолчанию 30 запросов в минуту, настройка —
`RATE_LIMIT_AUTH_RPM`, 0 — выключить). При превышении — ответ 429 на языке
пользователя.

## Не входит (осознанно)

- Выход на всех устройствах из UI (бэкенд умеет — ручки нет).
- Повторная отправка письма подтверждения — добавить, когда появится
  реальная жалоба на потерянное письмо.

## Приёмка → тесты

Интеграционные — `server/tests/api/`, e2e — `web/e2e/`. Карта
обновляется в той же правке, что и тест.

- Регистрация: аккаунт создаётся и вход сразу; дубликат и слабый пароль
  отклоняются — `register_login_me_flow`,
  `register_rejects_duplicates_and_weak_passwords` (auth.rs).
- Вход: неверная пара отклоняется без уточнения —
  `login_rejects_wrong_password` (auth.rs).
- Сессия: refresh ротируется, украденный старый токен мёртв —
  `refresh_rotates_and_old_token_dies`; выход отзывает сессию —
  `logout_revokes_session` (auth.rs).
- Восстановление: одинаковый ответ про любой email, одноразовый токен,
  отзыв сессий — `password_reset_full_flow` (auth_recovery.rs).
- 2FA: включение по QR, вход с кодом, отключение —
  `totp_two_factor_full_flow` (auth_totp.rs).
- Подтверждение почты: письмо, одноразовая ссылка, `email_verified` —
  `registration_sends_email_and_link_verifies_once`,
  `garbage_token_rejected` (auth_verify.rs).
- Защита от перебора: 429 при превышении частоты —
  `auth_requests_are_rate_limited_per_ip` (hardening.rs).
- Роли: проверка на бэкенде, admin шире user —
  `admin_can_delete_foreign_item` (items.rs),
  `promote_admin_changes_role` (ops.rs).
- Сквозной путь: «регистрация, создание записи, выход и повторный вход»
  (web/e2e/item.spec.ts).
- Ошибки локализованы ru/en —
  `api_errors_follow_accept_language_with_plurals`,
  `locales_have_identical_key_sets` (i18n.rs).
- Вход через VK/Яндекс — НЕТ ТЕСТА: внешний провайдер, проверка руками
  по `docs/oauth.md`.
- Пароли и секреты не попадают в логи — НЕТ ТЕСТА: держится на
  код-ревью (долг в `docs/backlog.md`).
