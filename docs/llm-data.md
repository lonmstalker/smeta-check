# LLM и данные пользователей: согласие, трансграничка, фикстуры

Итоги разведки к плану `docs/plans/2026-07-llm-integration.md`
(2026-07-31). Здесь — подробности и источники; решения — в плане.

## Согласие на обработку фото нейросетью

Разведка по практике (Яндекс, Сбер, Notion, Ivideon, Grammarly):
никто не пишет на кнопке «файл уйдёт в OpenAI»; стандарт — строка
у формы + честный раздел в политике конфиденциальности. Набор:

1. Непредзаполненная строка у формы загрузки фото: «Фото обработает
   нейросеть (без сохранения и без обучения на ваших данных).
   Персональные данные для проверки не нужны — можете замазать ФИО
   и телефоны. Продолжая, вы принимаете политику». Финальную
   формулировку вычитывает юрист. Для зарубежного провайдера
   добавляется «сервис за пределами РФ».
2. Пункт-гарантия в правилах: «пользователь подтверждает, что
   вправе загружать документ и данные третьих лиц в нём» (образец —
   оферты Ivideon п. 4.1/4.5, FriendWork п. 7.2).
3. Раздел про ИИ-провайдера в политике: кто, зачем, сроки хранения,
   «не хранит и не обучается» (образец — Notion AI: провайдеры
   названы поимённо, ретеншн указан).
4. Технически: ZDR-маршрутизация и `data_collection: deny` в
   аккаунте OpenRouter — данные не хранятся и не идут в обучение;
   именно это делает пункты 1 и 3 честными.
5. Разовая консультация юриста — трансграничная передача и
   уведомления РКН (см. ниже). Час консультации дешевле
   минимального штрафа 100–300 тыс. ₽.

Тот же набор покрывает будущее применение «сметы пользователей для
ценовой базы» (`docs/price-data.md`): гарантия + согласие.

## Трансграничная передача ПДн

«ПДн за границу» — не запрет, а разрешение с отдельным
уведомлением РКН (ст. 12 152-ФЗ). Но США вне перечня стран с
адекватной защитой: РКН рассматривает уведомление 10 рабочих дней
и вправе запретить передачу — путь легальный, но рисковый. Выходы:

- **Российский провайдер с OpenAI-совместимым API** — снимает
  вопрос целиком: у Yandex AI Studio OpenAI-совместимый API
  официальный, vision-модели хостятся в РФ
  (yandex.cloud/en/docs/ai-studio/concepts/openai-compatibility);
  GigaChat — через OpenAI-адаптер Сбера gpt2giga
  (github.com/ai-forever/gpt2giga). Архитектура клиента (смена
  провайдера тремя переменными) делает переход бесплатным.
- **Обезличивание до отправки** — для текста работает (прокси
  вырезает ФИО), для фото дорого: чтобы найти ФИО, нужен OCR.
- **Уведомление РКН и ожидание** — стратегию выбирает юрист.

Решение плана: прод-дефолт для пользовательских фото — российский
провайдер (если проходит планку качества F0), OpenRouter — для
разработки и задач без ПДн (экстракция публичных прайсов).

Источники: securegpt.ru/blog/ai-personal-data-legal-risks,
comply.ru/tpost/c43ezsout1, cisoclub.ru/transgranichnaja-
peredacha-pdn-pravovye-osnovanija, habr.com/ru/companies/just_ai/
articles/946392.

## Где брать фото смет для замера (F0)

Настоящих телефонных фото смет в открытом рунете почти нет (3–7
шт. за час ручного поиска). Зато чужих реальных смет как
PDF/скриншотов — десятки:

- mir-rem.ru/about/smeta — 22 PDF реальных смет по объектам
  (лучший источник разнообразия чужих шаблонов; содержат адреса
  и реквизиты — только локально);
- pikabu.ru/story/smeta_na_remont_kvartiryi_v_moskve_8628383 —
  3 изображения сметы подрядчика; лента pikabu.ru/tag/Смета;
- t-j.ru/ya-sovsem-ne-economil-na-remonte — сканы смет фирмы;
- forumhouse.ru/threads/444585 (тред «анализ смет») — смотреть
  живым браузером, антибот;
- smetdlysmet.ru/primery_smet — 130+ xls официальных смет
  (другой жанр, для разнообразия).

Использование опубликованных авторами изображений для локального
внутреннего тестирования приемлемо (ст. 1273 ГК РФ); в git и
публичные датасеты не класть, массово не скрапить.

Состав корпуса F0 и правила git — в плане (раздел «Закрыто
разведкой»). Главное правило: всё чужое — локально; в git идут
только распечатки наших xlsx.

## Рукописный класс (разведка 2026-07-31)

Рукописных СМЕТ РАБОТ публично почти нет (подтверждено повторным
поиском: выдача по «смете» — почти целиком печатный Excel).
Найденное и заменители:

- Подтверждённый образец: рукописный товарный чек со стройрынка в
  статье Т—Ж «Как составить смету» (t-j.ru/guide/smeta) — скоропись,
  таблица, печать, мятый лист.
- **Соседний подкласс — рукописные товарные чеки со стройрынков**:
  20–50 настоящих фото легко находятся в Яндекс.Картинках («товарный
  чек от руки заполненный стройматериалы») — тот же визуальный тип
  (кириллическая скоропись + числа + таблица + печать).
- Датасеты русской рукописи для добивки (текст, не таблицы):
  Cyrillic Handwriting Dataset (Kaggle, CC0), HWR200 (HuggingFace,
  Apache-2.0), school_notebooks_RU (HuggingFace, MIT). HKR не
  брать: лицензия NC + заявка.
- Бенчмарки VLM на кириллической рукописи: специализированного нет;
  косвенно (habr.com/ru/articles/895664, technologika.ru — тест 7
  систем на рукописных формах) «стабильных 95%+ не достигает никто»,
  лидеры — Gemini Flash и лёгкие GPT; русская скоропись тяжелее
  латиницы (CER 2–3% уровня IAM ждать не стоит).

Вывод: класс «рукопись» в F0 = 20–50 реальных чеков (соседний
подкласс) + 5–10 самодельных рукописных смет разными почерками
(только ради специфики «работы+расценки»); ожидание — планку
рукопись скорее не пройдёт, тогда класс уходит за честную
деградацию («распозналось мало — пришлите файлом»).
