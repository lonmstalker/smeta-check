# Интерфейс: единый стиль

## Каркас

- Компоненты — только shadcn/ui из `components/ui` (Button, Input, Card...).
  Нет нужного — `pnpm dlx shadcn@latest add <имя>`, не самопис.
- Страница: `<main className="mx-auto max-w-xl space-y-6 p-8">`, заголовок
  `text-3xl font-bold`. Отступы — шкала Tailwind (2/4/6/8), без пикселей.
- Цвета — только токены темы (`text-muted-foreground`, `bg-muted`,
  `text-destructive`...), не сырые (`text-gray-500` — нельзя): тёмная тема
  должна работать сама.
- Ссылки-кнопки: `<Button render={<Link to=... />}>текст</Button>`
  (Base UI; `asChild` здесь нет).

## Состояния — у каждого экрана их четыре

1. Загрузка: текст `common.loading` или скелет; страница не «прыгает».
2. Пусто: человеческая подсказка, что сделать (`estimates.empty` — образец).
3. Ошибка: `<FormError error={...}/>` — сообщение уже локализовано бэком;
   не показывать коды и стектрейсы.
4. Данные.

Формы: `disabled={busy}` на submit-кнопке (без двойных отправок), ошибка
рядом с формой, автофокус на первом поле шага, правильные `autocomplete`
(`email`, `current-password`, `new-password`, `one-time-code`).

## Тексты (и анти-slop текста)

- Все строки — через `t('ключ')` из локалей; количественные — только через
  `{count}` с формами `_one/_few/_many` (ru).
- Коротко и по-человечески: «Пока пусто — добавьте первую запись», а не
  «В данный момент отсутствуют записи в системе».
- Запрещено: канцелярит («данный», «осуществить», «функционал»),
  AI-штампы («Добро пожаловать в мир...», «Погрузитесь...», «Раскройте
  потенциал...»), восклицания и эмодзи в системных текстах, пустые
  маркетинговые эпитеты («мощный», «инновационный»).
- Ошибки говорят, что делать дальше, а не кто виноват.

## Дизайн (анти-slop)

- Никаких: фиолетово-градиентных hero-блоков, стеклянных карточек с
  свечением, эмодзи вместо иконок (иконки — lucide-react), теней ради
  теней, анимаций без функции.
- Плотность важнее эффектности: меньше рамок и заливок, больше воздуха
  и выравнивания. Один акцентный цвет (primary), остальное нейтральное.
- Сомневаешься — посмотри существующие страницы и повтори их ритм.

## Проверка «живого» поведения (анимации, клики)

- Скриншот не показывает движение. Для проверки анимаций и реакции на клик
  есть `cd web && pnpm motion <url> [селектор]`: печатает компактный JSON
  (какие анимации сработали, длительность/easing, что изменилось в DOM,
  плавно или дёргано, какие запросы ушли) и кладёт 3 кадра до/в момент/после
  в `web/test-results/motion/`. Сначала читай JSON, кадры — только если нужно.
