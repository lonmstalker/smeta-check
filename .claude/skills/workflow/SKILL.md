# Процесс работы (простой, для стартапа)

Цель: человек со стороны разбирается в проекте только по документам, не
читая код. Документов четыре, лишней бюрократии нет.

## Документы

| Файл | Что там | Когда обновлять |
|------|---------|-----------------|
| `docs/product.md` | что за продукт, роли, бизнес-модель | при смене продуктовых решений |
| `docs/architecture.md` | как устроена система и почему | при новых доменах/технологиях |
| `docs/usecases/UC-xxx-*.md` | сценарии фич словами | новая заметная фича |
| `docs/plans/ГГГГ-ММ-*.md` | план работ крупнее одной фичи | старт крупной работы |
| `docs/oauth.md` и другие runbook | пошаговая настройка руками (провайдеры, операции) | при смене настройки |
| `docs/backlog.md` | очередь будущего: бизнес и техника раздельно | долг/идея, отложенные осознанно |
| `docs/journal.md` | история: что и зачем сделано | КАЖДАЯ задача, запись сверху |

## Ход заметной задачи (новая фича)

1. **Use case сначала.** Создай `docs/usecases/UC-<номер>-<имя>.md` по
   образцу UC-001: зачем (бизнес-ценность), актёры, сценарии по шагам,
   что осознанно НЕ входит, критерии приёмки. Пиши словами, без кода.
2. **Контракт.** Спроектируй эндпоинты и DTO, опиши в utoipa-аннотациях,
   `make gen-api` — фронт сразу получает типы.
3. **Реализация** по слоям: миграция -> домен -> HTTP -> тесты -> UI.
   Детали — скилл `new-feature`.
4. **Сдача.** `make verify` зелёный; обнови use case, если по ходу что-то
   поменялось (док должен совпадать с реальностью); добавь запись в
   `docs/journal.md`; при изменении архитектуры — обнови architecture.md.

## Мелкая задача (фикс, правка)

Только код + тест + запись в журнал. Use case не нужен.

## Бэклог: долги и идеи

Увидел долг или идею, но делать сейчас не будешь — запись в
`docs/backlog.md`, в секцию «Бизнес» или «Техника». На входе — фильтр
честности (описан в самом файле): кому больно, цена бездействия,
триггер, секция; нет любого из четырёх ответов — не записываем,
сомнительное отдаём скептику свежей моделью. Журнал долги не хранит —
он может упомянуть «долг записан в бэклог», жить долг обязан в бэклоге.

## План работ (крупнее одной фичи)

Когда работа — это пачка связанных задач (внешнее ревью, новый большой
кусок продукта, серия фич), сначала план: `docs/plans/ГГГГ-ММ-<тема>.md`,
образец — `docs/archive/plans/2026-07-harness-and-components.md`.
Одна фича плана не требует.

Сверху — статус: ЧЕРНОВИК / В РАБОТЕ / ВЫПОЛНЕНО (дата) /
ОСТАНОВЛЕН (дата, причина словами).

**До реализации план обязан ответить на вопросы:**

1. Что уже есть в коде? Сверить каждый пункт с репозиторием, повторно
   не делать — отдельным разделом «Что уже есть».
2. Что осознанно НЕ делаем и почему? Раздел-антисписок.
3. Как режется на задачи? Каждая задача — id, размер (S/M/L), приёмка
   словами; L обязательно дробить. Каждая заканчивается зелёным
   `make verify` и записью в журнал.
4. Каков порядок и зависимости? Что защищает дальнейшую работу
   (проверки, harness) — первым.
5. Какие вопросы открыты? Блок «Вопросы» вверху плана: спорные решения,
   на которые нужен ответ человека. Пока ключевые открыты — реализацию
   не начинать; закрытые переносить в текст плана как решения с причиной.

Как составить план и проверить его свежей моделью (pre-mortem и другие
ракурсы) — скилл `planning`.

**По ходу и после.** План — не журнал: история остаётся в `journal.md`.
Разошёлся с реальностью — фиксируй в разделе «Что сделано иначе и почему»
в конце плана.

**Потолок 400 строк действует и для плана.** Работа не влезает — планируй
волнами: детально расписывай только ближайший этап, дальнейшее — короткий
раздел «Дальше» списком тем без детализации. Следующий план пишется,
когда текущий ВЫПОЛНЕН, — по свежей реальности, а не по догадкам
месячной давности.

**В `docs/plans/` лежат только живые планы.** Поставил ВЫПОЛНЕНО — в том
же изменении перенеси файл в `docs/archive/plans/`. Старт нового плана —
момент ревизии: заглохший план В РАБОТЕ закрой статусом ОСТАНОВЛЕН
(причина словами) и тоже перенеси в архив.

## Запись в журнале — формат

```markdown
## ГГГГ-ММ-ДД — Короткий заголовок

**Что сделано.** 1-5 предложений простым русским, без жаргона.
**Зачем.** Одно-два предложения о пользе.
**Как проверить.** Команды или шаги руками.
```

Пиши для нетехнического читателя: «робот открывает настоящий браузер»
лучше, чем «e2e-тесты на playwright».

## Журнал не разрастается бесконечно

Потолок любого файла (и доков тоже) — 400 строк, `make check` следит.
Когда `docs/journal.md` подходит к лимиту — перенеси старейшие записи в
`docs/archive/journal-ГГГГ.md` (архив проверкой не ограничен), свежие
оставь на месте. То же с другими растущими доками: дели по темам/периодам.
