# Проверка дизайна: искать проблемы, а не подтверждать

Один скриншот и вердикт «выглядит хорошо» — не проверка. Мерцание не видно
на статичном кадре, «не тот цвет» не виден без эталона, смещение в 5px не
видно на полноэкранном снимке. Проверка = активный поиск проблем; «проблем
нет» можно сказать только приложив артефакты по каждому пункту ниже.

## Рамка

Ставь себе задачу «найди минимум 5 проблем на этом экране и отсортируй по
серьёзности», а не «проверь, что всё ок». Не нашёл пяти — докажи по
чек-листу, почему их нет. Подтверждать корректность и искать дефекты —
разные режимы; работает только второй.

## Протокол

Кадры и диффы складывай во временный каталог (scratchpad), не в репозиторий.

1. **Мерцание: серия кадров, не один.** На «спокойной» странице (данные
   загружены, ничего не трогаем) сними 6–8 скриншотов с шагом ~150 мс.
   Сравни: одинаковые кадры дают одинаковый хеш (`shasum`); хеши разошлись —
   что-то живёт само по себе. Найди отличающийся регион (пиксельный дифф или
   зум) и причину в коде: нестабильный `key` → remount, transition на
   mount, повторная загрузка картинки, бесконечный ре-рендер. Дополнительно:
   `document.getAnimations().length` на странице в покое — идущие анимации
   без причины подозрительны.

2. **Цвета и выравнивание: числа вместо глаз.** Выполни JS на странице:
   - цвет элемента против токена темы:
     `getComputedStyle(el).color` сравнить со значением токена
     (`getComputedStyle(document.documentElement).getPropertyValue('--primary')`
     и т.п.); сырой цвет мимо токенов — дефект сам по себе (скилл ux);
   - выравнивание: `getBoundingClientRect()` у элементов, которые должны
     стоять на одной оси — расхождение больше 1px = проблема, назови число;
   - переполнение: `document.documentElement.scrollWidth > innerWidth` =
     горизонтальный скролл, всегда дефект.

3. **Зум на детали.** Полноэкранный скриншот мельчит. Подозрительные места
   (стыки карточек, иконки в кнопках, базовые линии текста) смотри зумом
   на регион, а не на всю страницу.

4. **Матрица состояний.** Минимум: тёмная тема (кнопка «Сменить тему») и
   мобильная ширина 375px — там ломается чаще всего. У экрана четыре
   состояния (загрузка/пусто/ошибка/данные — скилл ux): проверь те, что
   задеты правкой; загрузку лови троттлингом сети или заглушкой API.

5. **Консоль.** Ошибок и предупреждений React нет. Предупреждение про key
   или гидратацию — это и есть причина мерцания из п.1.

6. **Свежий взгляд.** Если вёрстку в этой сессии писал ты сам — финальный
   вердикт даёт сабагент: ему передаются только скриншоты и этот чек-лист,
   задача — найти проблемы. Автору своей вёрстки верить нельзя.

## Автоматика: закрепи найденное

Ручная проверка разовая, регресс ловят тесты (`web/e2e/`):
- `visual.spec.ts` — скриншот-эталоны трёх ширин (CI-джоб visual);
  изменил страницу — обнови эталоны, добавил страницу — добавь эталон;
- `layout.spec.ts` — ARIA-схема структуры страницы;
- `motion.spec.ts` — kill-switch анимаций.
Проблему, найденную руками, закрывай тестом в этих файлах — иначе вернётся.

## Вердикт

Либо список проблем по серьёзности (что, где, чем показано — кадр, число,
строка консоли), либо «проверено» с перечнем артефактов по пунктам 1–5.
Слова «выглядит хорошо» без артефактов вердиктом не являются.
