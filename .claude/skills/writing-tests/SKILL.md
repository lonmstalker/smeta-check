# Тесты: инфраструктура и правила

Принцип shift-left: ошибка должна умереть на ближайшем к коду уровне —
юнит быстрее интеграционного, интеграционный быстрее e2e, всё быстрее
прода. Реальная БД, а не моки SQL.

## Бэкенд (server/tests/api/)

Один тест = одна строка подготовки:

```rust
use crate::common::spawn_app;

#[tokio::test]
async fn my_scenario() {
    let app = spawn_app().await;                 // чистая БД + все миграции
    let (token, email) = app.register_user().await; // готовый пользователь
    let res = app.post_auth("/api/items", json!({"title": "x"}), &token).await;
    assert_eq!(res.status, StatusCode::CREATED);
}
```

Что уже есть в `TestApp` (common.rs) — НЕ переизобретать:
- `get/post/post_auth/delete_auth/request` -> `TestResponse{status, body, cookies}`;
- `register_user`, `promote_to_admin`, `refresh_token_of`, `last_email_to`
  (письма из dev-ящика outbox_emails);
- запросы идут через `oneshot` без открытия портов и сети.

Скорость («олимпиадные» пути):
- если dev-БД поднята (`make dev`), `make test` подставит TEST_PG_URL —
  каждому тесту создаётся БД на общем сервере за миллисекунды, контейнеры
  не поднимаются вовсе;
- без TEST_PG_URL — testcontainer на тест, Drop гарантирует очистку.

Правила: тест не зависит от порядка и других тестов; данные создаёт сам;
время/uuid не фиксируй жёстко.

## Фронт юнит (web/src, vitest)

```tsx
import { guestApi, mockApi, renderApp } from './test-utils'

test('...', async () => {
  guestApi({ '/api/items': () => [{ id: 1, title: 'x' }] })  // мок сети
  renderApp(<App />)                    // реальные провайдеры приложения
  expect(await screen.findByText('x')).toBeInTheDocument()
})
```

- `mockApi`: незамоканный путь -> 500, тест сразу видит лишний запрос.
- Никаких `vitest --watch` в автоматике и хуках — только `pnpm test`
  (это `vitest run`); watch-процессы зависают в фоне и теряются.
- Таймауты уже стоят в vite.config.ts — не удалять.

## E2E (web/e2e, playwright)

- Фикстура `user` из `fixtures.ts` даёт зарегистрированного и вошедшего
  пользователя — не повторяй регистрацию шагами в каждом тесте.
- Селекторы — роли и видимые тексты (getByRole/getByPlaceholder), локаль
  стенда ru-RU.
- Стенд поднимает и гасит сам Playwright (`scripts/e2e-server.sh`).
- E2E — только ключевые пользовательские пути (вход, основной сценарий);
  ветвления и ошибки — уровнем ниже.

## Карта «Приёмка → тесты» в use case

У каждого use case есть раздел «Приёмка → тесты»: атомарный критерий —
имя теста (rust-функция или русский заголовок спека) либо честное
«НЕТ ТЕСТА» с долгом в журнале. Добавил/переименовал/удалил тест по
сценарию UC — обнови карту в той же правке. Заголовки тестов фронта —
по-русски, читаются как сценарий.

## Живое поведение (анимации, реакция на клик)

Инструмент: `cd web && pnpm motion <url> [селектор]` — JSON-сводка
(анимации с duration/easing, DOM-изменения, долгие кадры, запросы,
ошибки консоли) + 3 кадра в `web/test-results/motion/`. Стенд сам не
поднимает — нужен работающий фронт (dev или e2e-стенд). В `make verify`
не входит: это инструмент ручной проверки, не автотест.

Когда прогонять: правишь всё, что появляется/исчезает/движется —
модалки, тосты, меню, смену темы, переходы страниц, скелетоны.

Качественный тест-кейс для motion:
- один кейс = одно действие (загрузка страницы или один клик);
  вывод сверяй по числам из JSON, а не «на глаз» по кадрам;
- проверяй обе стороны: что должно анимироваться (duration 100–400 мс,
  easing не linear) и чего быть не должно (`longFrames > 2`,
  `consoleErrors`, лишние `requests`, DOM-шум вне затронутого места);
- «abrupt» — не всегда баг: мгновенная реакция допустима, если осознанна
  (ux-скилл запрещает анимации без функции); решение фиксируй словами
  в журнале или в use case;
- кадры открывай только при подозрительном вердикте — экономия контекста;
- бюджет: один прогон ~5 с; кадры перезаписываются каждым прогоном.

## Бюджеты (превысил — упрощай тест, а не жди дольше)

- юнит < 100 мс; интеграционный < 2 с; один e2e-сценарий < 15 с;
  `make verify` локально < 5 мин.
- Все уровни обложены таймаутами (vitest/playwright/CI timeout-minutes) —
  зависший тест падает, а не висит в фоне.
